HTML5
Fundamentals

Structure, semantics, tabular data, forms, and native validation — without a single line of CSS or JavaScript.

HTML describes
structure, not style.

HTML — HyperText Markup Language — tells the browser what content is on a page and what role each piece plays: a heading, a paragraph, a list, a link, a form. It says nothing about colour, font, or layout. That is CSS's job.

A browser can render HTML with no CSS at all and the document remains fully readable. That is its greatest strength.

Module 1

The HTML5 Boilerplate

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport"
        content="width=device-width, initial-scale=1.0">
  <title>BAUET Web Programming</title>
</head>
<body>

  <h1>Hello, CSE Department!</h1>
  <p>HTML is the backbone of the web.</p>

</body>
</html>

<!DOCTYPE html> activates HTML5 mode. Without it, browsers fall back to legacy quirks mode.

Module 1

Inside the <head>

What lives in the head?

The <head> is invisible to users. It holds metadata that the browser, search engines, and social media scrapers read.

TagPurpose
<title>Text shown in browser tab and search results
<meta charset>Character encoding — always UTF-8
<meta name="viewport">Enables correct mobile scaling
<meta name="description">Search-engine page summary (160 chars)
<link rel="stylesheet">Links an external CSS file
<script src>Links an external JavaScript file
 
<head>
  <!-- always first -->
  <meta charset="UTF-8">

  <!-- mobile scaling -->
  <meta name="viewport"
        content="width=device-width,
                 initial-scale=1.0">

  <!-- browser tab title -->
  <title>BAUET Lab Portal</title>

  <!-- SEO description -->
  <meta name="description"
        content="BAUET CSE lab resources">

  <!-- external CSS -->
  <link rel="stylesheet"
        href="style.css">
</head>

target="_blank" opens the link in a new tab. Use it for external sites so users do not lose their place on your page.

Images & Figure

alt is mandatory. If the image fails to load, or a screen reader is used, the alt text is what the user gets. An empty alt="" is valid only for purely decorative images.

A tag's name
is its promise.

When you write <div id="nav">, you are making a visual promise that only CSS can keep. When you write <nav>, you are making a structural promise that the browser, search engine, and screen reader all understand — with or without CSS.

A blind user navigates by landmark. A search engine indexes by landmark. A developer reads by landmark. Semantic HTML is the foundation that makes all three possible simultaneously, for free, with zero extra effort.

Module 5

Structural Semantic Elements

Non-semantic — machines cannot infer purpose

<div id="header">
  <div id="nav">Links</div>
</div>
<div id="content">
  <div class="post">Article</div>
</div>
<div id="footer">Copyright</div>

Semantic — purpose is self-evident

<header>
  <nav>Links</nav>
</header>

<main>
  <article>
    <section>Content</section>
  </article>
  <aside>Sidebar</aside>
</main>

<footer>Copyright</footer>

Semantic Elements — Reference

ElementRoleWhere to use
<header>Introductory content for page or sectionTop of page, or top of an article
<nav>Block of navigation linksPrimary menu, breadcrumb, sidebar nav
<main>Primary content of the documentOnce per page only
<article>Self-contained, independently distributable contentBlog post, news item, lab report
<section>Thematically related content with a headingChapters, tab panels, grouped content
<aside>Tangentially related contentSidebar, callout, related links
<footer>Closing content — author, copyright, linksBottom of page or article

Module 6

Tables — colspan & rowspan

<!-- colspan merges across columns -->
<td colspan="3">
  Lunch Break (all halls)
</td>

<!-- rowspan merges across rows -->
<td rowspan="2">
  Web Lab (2 hours)
</td>

colspan = how many columns this cell occupies.
rowspan = how many rows this cell occupies.
The cells it "absorbs" must be removed from the markup.

Module 7

Forms — Structure & Label Binding

<form action="#" method="POST">

  <fieldset>
    <legend>Student Information</legend>

    <!-- for= must match id= -->
    <label for="n">Full Name:</label>
    <input type="text"
           id="n"
           name="fullname">

    <label for="e">Email:</label>
    <input type="email"
           id="e"
           name="email">

  </fieldset>

  <button type="submit">Submit</button>
  <button type="reset">Clear</button>

</form>

Clicking a correctly bound <label> focuses its input. This is a usability and accessibility requirement, not optional.

Module 8

Native Validation — No JavaScript

<!-- required blocks empty submit -->
<input type="text" required>

<!-- placeholder shows hint text -->
<input type="text"
       placeholder="Your full name">

<!-- pattern enforces a regex -->
<input type="text"
       pattern="[0-9]{9}"
       title="Exactly 9 digits"
       required>

<!-- min/max for numbers and dates -->
<input type="number"
       min="1" max="100">

<!-- accept filters file picker -->
<input type="file"
       accept=".pdf,.png">

Audio & Video

<!-- Video player -->
<video controls width="480">
  <source
    src="lecture.mp4"
    type="video/mp4">
  Your browser cannot play video.
</video>

<!-- Audio player -->
<audio controls>
  <source
    src="podcast.mp3"
    type="audio/mpeg">
</audio>

<!-- iFrame embed -->
<iframe
  src="https://maps.google.com"
  width="100%"
  height="300"
  loading="lazy"
  allowfullscreen>
</iframe>
AttributeEffect
controlsShows play/pause/volume bar
autoplayStarts playing immediately (muted required)
loopPlays again when finished
mutedStarts without audio
loading="lazy"Defers iframe load until scrolled near

Always provide a <source> child with type set correctly. The fallback text inside <video> is shown if the browser cannot play the file.

Bringing it together

A Complete Form in Context

Every concept from modules 7–8 combined: semantic structure, fieldset grouping, all input types, and native validation.

ElementUsed for
<form>Container — defines action and method
<fieldset>Groups related inputs visually and semantically
<legend>Caption for a fieldset
<label>Describes an input — must link via for/id
<input>Data entry — type defines the control
<select>Dropdown menu
<textarea>Multi-line free text
<button>Submit, reset, or generic action

The structure you build today will be exactly what gets styled in the CSS lab next week. Clean semantic HTML makes CSS dramatically easier to write.

Checklist before submitting any form task:
— Every input has a label bound via for/id
— Required fields have required
— Phone and ID fields have pattern
— File inputs have accept
— Page uses semantic layout tags
